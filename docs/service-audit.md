# Service audit

The rule: every recognized resource or service vehicle gets unlimited stock for the service it provides, unless that service already doesn't deplete. Each row below was checked against the source named in the *Verified in* column:

- Antistasi Ultimate: `SilenceIsFatto/A3-Antistasi-Ultimate` at commit `ac4eb28`.
- ACE3: `acemod/ACE3` at commit `a17210f` (2026-10-17).
- CBA_A3: `CBATeam/CBA_A3` at commit `cd4361a` (2026-10-10).
- Arma 3 commands and events: `acemod/arma3-wiki`, the parsed BI wiki, `dist` branch, game version 2.22.

## RHS and CUP

RHS and CUP service trucks use the same config fields: vanilla `transportFuel`, `transportAmmo` and `transportRepair`. ACE3's compat addons add `ace_refuel_fuelCargo` and `ace_rearm_defaultSupply` to them. For example `compat_rhs_afrf3/CfgVehicles.hpp` sets `RHS_Ural_Fuel_MSV_01` to 10000 l and `RHS_Ural_Ammo_Base` to 1200, and `compat_cup_vehicles/compat_cup_vehicles_refuel/CfgVehicles.hpp` covers the CUP MTVR, Ural, Kamaz, T810 and V3S refuel trucks. The config-based detection above therefore covers them without class lists. No RHS- or CUP-specific code is needed, so the `compat/` folder holds only the ACE integration.

## What "unlimited" does and doesn't change

- **Only the service stock changes.** A fuel truck's own `fuel` drains normally. Vehicles that are not service sources keep normal finite fuel, ammunition and damage.
- **Receiving vehicles are serviced normally,** up to their own capacity. Engine, ACE and garage logic decide how much they take.
- **No per-frame loop is used.** Vanilla stock is refilled from the `Service` event, which fires only while servicing happens. ACE fuel uses ACE's own infinite flag, with no refills at all. ACE limited rearm and the Antistasi garage each use one slow server timer, because neither raises an event when stock is used.
